# Credit Card Fraud Detection & Analytics Dashboard

End-to-end fraud detection system built on the Kaggle "Credit Card Fraud Detection" dataset (284,807 transactions, 0.173% fraud rate), comparing seven supervised and unsupervised modeling approaches and serving the results through an interactive Streamlit analytics dashboard.

**[Live Demo](#) &nbsp;•&nbsp; [Dashboard Screenshots](#screenshots) &nbsp;•&nbsp; [Results](#results)**

---

## Overview

Fraud detection is a canonical extreme class-imbalance problem — fewer than 0.2% of transactions in this dataset are fraudulent, which means naive accuracy is meaningless (a model that never predicts fraud still scores 99.8% accuracy). This project treats that constraint as the central design problem rather than an afterthought:

- Every model is evaluated on **PR-AUC, Precision, Recall, and F1**, not accuracy
- Class imbalance is addressed with **two competing strategies** (class-weighting vs. SMOTE) and compared head-to-head rather than assuming one is better
- Decision thresholds are tuned using a **cost-based approach** (assumed cost of a missed fraud vs. a false alarm), not left at the default 0.5
- Supervised classifiers are benchmarked against **unsupervised anomaly detection** (Isolation Forest, a PyTorch Autoencoder), to test whether label-free approaches can compete

The result is shipped as a Streamlit dashboard — not a notebook — so the modeling work is explorable by a non-technical reviewer, not just readable as code.

**Key finding:** Random Forest outperformed both Logistic Regression and XGBoost on PR-AUC, the primary metric for this problem. Interestingly, **SMOTE did not meaningfully outperform class-weighting** on either model family — a useful, slightly counterintuitive result, since SMOTE is often treated as a default best-practice rather than one option among several worth testing.

## Methodology

**1. Exploratory Data Analysis**
Quantified the class imbalance (0.173% fraud), compared transaction amount distributions by class, and ranked the anonymized `V1`–`V28` PCA features by correlation with the fraud label.

**2. Baseline Model**
Logistic Regression on scaled features, establishing the minimum bar every subsequent model has to beat.

**3. Tree-Based Models**
Random Forest and XGBoost, benchmarked against the linear baseline and each other.

**4. Imbalance Handling — Compared, Not Assumed**
Each classifier trained three ways: unmodified, with `class_weight='balanced'` / `scale_pos_weight`, and with SMOTE oversampling (applied only to the training split, never to the test set, to avoid data leakage).

**5. Threshold Tuning**
Moved off the default 0.5 cutoff using a cost function — `cost = (false negatives × cost of missed fraud) + (false positives × cost of a false alarm)` — and selected the threshold that minimizes total assumed cost.

**6. Unsupervised Anomaly Detection**
- **Isolation Forest**, trained without labels, flags transactions that are statistically easy to isolate from the rest of the data.
- **Autoencoder** (PyTorch), trained *only* on legitimate transactions, flags transactions with high reconstruction error — i.e., transactions that don't look like anything the model learned as "normal."

**7. Final Comparison**
All seven approaches evaluated on the same held-out, stratified test set using identical metrics, surfaced in the dashboard's Model Comparison page.

## Project Structure

```
credit-card-fraud-detection/
├── train_models.py        # Trains all 7+ models, saves every artifact to models/
├── app.py                 # Streamlit dashboard — loads artifacts, never retrains
├── src/
│   └── model_utils.py     # Shared Autoencoder architecture + feature schema
├── notebooks/
│   └── fraud_detection.ipynb   # Original exploratory analysis
├── data/
│   └── creditcard.csv     # Kaggle dataset (not included — see Setup)
├── models/                # Generated: trained models, scalers, metrics
└── pyproject.toml
```

The project deliberately separates **training** (`train_models.py`, run once) from **serving** (`app.py`, loads only pre-saved artifacts). This mirrors how ML systems are structured in production — training and inference are different concerns with different performance requirements — and means the dashboard starts in seconds rather than retraining models on every page load.

## Setup

**Prerequisites:** Python 3.12+, [uv](https://docs.astral.sh/uv/)

```bash
# 1. Clone and enter the project
git clone <repo-url>
cd credit-card-fraud-detection

# 2. Get the dataset
# Download creditcard.csv from the Kaggle "Credit Card Fraud Detection" dataset
# and place it at data/creditcard.csv

# 3. Create environment and install dependencies
uv venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS/Linux
uv pip install -e .

# 4. Train all models (~5-10 minutes)
python train_models.py

# 5. Launch the dashboard
streamlit run app.py
```

<a id="reproducing-results"></a>
Step 4 trains and saves: Logistic Regression ×3, Random Forest ×3, XGBoost ×2, Isolation Forest, and the PyTorch Autoencoder, along with both feature scalers, cost-optimal threshold, and all evaluation metrics — everything the dashboard reads.

## What This Project Demonstrates

- **Imbalanced classification**: handling a <0.2% minority class correctly, including choosing metrics that don't lie about performance
- **Rigorous comparison, not assumption**: testing SMOTE against class-weighting instead of defaulting to whichever is trendier
- **Decision-relevant evaluation**: cost-based threshold tuning, which maps model output to a business decision rather than stopping at AUC
- **Unsupervised modeling**: Isolation Forest and an autoencoder built and evaluated on equal footing with supervised models
- **Production-adjacent structure**: clean train/serve separation, cached model loading, no retraining on every request
- **Honest limitations**: the dashboard's About page explicitly states what this system does *not* do (see below)

---

## Limitations

- `V1`–`V28` are anonymized PCA components; their real-world meaning is unknown, which limits interpretability
- The dataset is historical (European cardholders, September 2013) — fraud patterns evolve, and this won't reflect current tactics
- Performance on this dataset is not a guarantee of performance on live, real-world transaction streams
- An anomaly flag from Isolation Forest or the Autoencoder means "statistically unusual," not "confirmed fraud"
- **This is a portfolio / applied-ML project, not a production fraud detection system.**
